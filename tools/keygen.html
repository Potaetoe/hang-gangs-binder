Key generator

Generates the keypair the portal encrypts to. Everything happens in this page — nothing is sent anywhere, and this file cannot reach the network.

Cannot run here

Serve this directory and open it over localhost: python -m http.server 8125 --directory tools, then visit http://localhost:8125/keygen.html.

Before you press the button

  • There is no recovery. Every submission is encrypted to this key. Lose the private half and the data is permanently unreadable — by you, by Cloudflare, by anyone.
  • Save two copies, today. A password manager and one other place. One copy is one dead laptop away from none.
  • The private half never goes in the repository, never in an email, never in a chat. Only the public half is published, and publishing it is what a public key is for.

Step one

P-256, for ECDH — the curve crypto.js and admin.html expect. Generating again replaces what is shown below; anything already saved keeps working, and anything already submitted stays readable only by the key it was encrypted to.

Step two — the public half

Paste this into apps/web/config.js

Safe to commit and safe to publish. It encrypts and cannot decrypt. The form refuses to submit while publicKey is null, so this is what opens the portal.

Step three — the private half

Save this file, then store it properly

This is the only copy. Nothing has written it to disk yet.

Hidden by default — a key on screen is a key in a screenshot, a screen share or over a shoulder. admin.html takes this file as-is.

Then

  • Put the line from step two in config.js and run python tools/check_web.py before pushing.
  • Make the second copy of the key file now, not later.
  • Close this tab. Nothing here is stored, so closing it is all the cleanup there is.

Why the key is generated here rather than anywhere else, and what happens when custody changes hands: see DESIGN.md and HANDOFF.md.
